# 原始提示词

---

参考ida mcp中的exe以及仓库中现有的代码，编写一个可以截留rtScreenshot并输出为视频流的mod。

mod需要能够适配tgc与netease两个版本（ida中Sky_dump为netease，Sky-32.2-260129为tgc），版本信息通过HTModLoader获取，模组架构模仿现有仓库中的文件。修改metabinary中的binarydescriptor以使其可以根据游戏版本不同读取不同的描述符列表。

ida符号名上的参数并不准确，需要根据反汇编推断实际参数。ida数据库的字符串列表不完整且无需考虑修复，且使用字符串列表会导致ida卡死，故请勿使用字符串查找，而是使用二进制查找。ida中的断言信息使用xorstr加密，可以选择自行解密以获取更为精确的推断。

src/skylink/中的文件不要添加除了需要的链接与还原的游戏实现以外的代码。满足上述要求的情况下可以自由添加需要的游戏声明链接与结构体声明。添加函数声明时需要使用METABINARY，现有代码提供了大量可以参考的实现。

代码架构参考当前代码仓库的分割模式，请勿在单文件内放置过多的类或函数，当且仅当这些函数确定除该文件外不可能有使用者或类之间存在强相关联性如内联子类、参数结构体时放置在同一个头文件中。

我们假定对象内部偏移量不稳定、随时可能随游戏版本而改变，故需要获取游戏对象与插入游戏时，尽可能使用hook，直接通过函数参数或返回值获取必要的游戏对象，而不要通过对象内部成员偏移量。游戏核心对象如SystemIO、Compositor、Game等均为单例，可以长期存储在mod中；反汇编推断出不为单例的同上，尽可能通过hook获取当前活跃实例。游戏对象尽可能作为句柄使用，而不是一个结构体，mod尽可能少地关心游戏对象内部。上述规则仅在无法通过合理的hook满足时允许特例，如一些仅在函数内部被读写且并没有直接获取函数的成员（CameraNode的矩阵等）。

游戏强相关的代码尽可能地在tgc/netease客户端间横向通用、不同时间的发布版本间纵向通用。

若发现现有代码存在严重影响mod运行的bug，停止编写并等待用户修复。

mod除发现来自自身的严重错误外（包含但不仅包含当确定会导致崩溃时），不允许通过断言等方式导致游戏崩溃。尽量将错误通过日志与窗口输出，并关闭mod的主要功能。若可以通过重试尝试修复错误，则重试。为满足本条规则，允许删除现有代码仓库中的断言并修改为错误码。HTModLoader API可以假定是稳定的，不会引发崩溃或返回意料之外的结果。

mod不可能被卸载，无需考虑主动清理，但仍需简单考虑游戏关闭时的错误处理。
